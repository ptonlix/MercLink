## Context

2026-10-09 更新：本轮用户已明确授权按方案实施前端，范围限于现有页面、交互与样式；实施记录见 `implementation/README.md`。主规格不自动同步，后端不改。

MercLink 是单店、以 Agent 为操作入口的商品服务。人工网页负责理解店铺与商品、找到 Skill，以及在自己的浏览器内登录和批准 Agent。此设计以 `docs/PRD.md`、`docs/ARCHITECTURE.md`、已生效规格及实际实现为依据，不把其他未归档变更当成授权范围。

已检查的实现与约束：

| 区域 | 当前实现 | 设计依据 |
| --- | --- | --- |
| 首页 | `LandingView` 已有店铺介绍、横向货架、平台页脚 | 保持店铺优先和数据来源，将货架重排为横幅及下方使用步骤 |
| 列表 | `ProductListView` 纵向文本；页面只接收 `cursor` | 做封面网格；保留游标分页，本期不增加搜索或目录筛选 |
| 详情 | `ProductView` 显示 offer、公开字段、全部可售规格 | 重排为商品图、价格、规格和属性；不建另一套商品详情 |
| 公开数据 | `loadLanding/loadProductList/loadProduct` 调用 public store/product seam | 页面、JSON-LD、API 继续使用同一份事实 |
| 授权 | 设备码页及 `BuyerAuthorizeView/MerchantAuthorizeView`；提交走现有 POST | 视觉围绕现有服务端步骤展开，不在客户端重写授权协议 |
| 店主 | `/admin` 仅登录和改密码 | 不加入商品、订单或经营看板 |
| 脚本 | `/authorize/account` 显示与撤销 API Key | 独立于 Agent 流程，不导入授权页导航 |

生效的 `public-pages` 要求暖纸色、衬线店名、绿色强调色，原本还限制平台入口只在页脚。用户最新要求将商品展示改为可滚动 banner，在下方放“查看更多”和分步使用介绍。本变更明确修改这两条首页规格，允许商品列表入口、平台名与 Skill 进入商品后的主体说明区；主规格在同步或归档前保持原文；本轮已获授权实施前端。API 与发现文件仍在页脚，店铺与商品仍先于平台介绍。

本次 HTML 是提案附件，内联 SVG 为示意封面，店名、地址、商品、库存、价格均为演示数据；不会进入生产 model 或对象存储。没有新增实际页面路由、授权能力或支付能力。

## Goals / Non-Goals

**Goals:**

- 人进入首页先识别这家店，进入详情能快速读懂价格、规格、库存和属性。
- 买家知道把买家 Skill 交给 Agent；店主知道把商家 Skill 交给 Agent，并在浏览器批准。
- 所有页面共用明确的排版与交互规则，手机端、键盘操作和禁用脚本时仍能使用核心内容。
- 方案写到“展示什么、操作后发生什么、由哪个现有文件实现、怎么验收”，供下一轮 apply 使用。

**Non-Goals:**

不做店铺装修系统、商品后台、商品推荐、购物车、人工网页下单、网页订单中心、商家注册、第二家店或支付宝回跳页。不改 JSON 外壳、API 路径、钱和库存的领域规则。不新增字体库、组件库、图标依赖和后端服务。

## Decisions

### 1. 视觉方向：一本能被 Agent 读懂的商品册

将“实体小店的商品册”作为视觉主体，系统能力在商品下方的分步介绍和授权页说明。记忆点放在有留白的横向商品横幅，周围保持克制；不堆经营指标、宣传口号和同形卡片。

| Token | 值 | 用途 |
| --- | --- | --- |
| Paper | `#F6F4EE` | 页面背景，沿用现有暖纸色 |
| Surface | `#FFFFFF` | 输入与详情规格区域 |
| Ink | `#26332B` | 主正文、标题 |
| Muted | `#60695F` | 次要说明，保持正文对比度 |
| Moss | `#4E653E` | 唯一品牌强调色、主按钮、价格 |
| Line | `#D8DDD1` | 有语义的边界、表格与分隔线 |

成功状态沿用深绿色；错误使用 `#A13E30` 配文字与图标，不只靠颜色区分。商品封面可以用商品自己的颜色；示例的淡紫、灰蓝不是新的品牌按钮色。

字体不下载：店名与少量大标题用 `"Iowan Old Style", "Songti SC", "Noto Serif CJK SC", serif`；正文用 `"Avenir Next", "PingFang SC", "Microsoft YaHei", sans-serif`；只有真实 ID 和路径使用等宽字体。标题 56/40/28px，正文 16px、行高 1.65，辅助文字 13–14px，价格采用等宽数字。移动端店名收为 38px。

最大内容宽度 1160px；桌面左右至少 40px，手机 20px。间距采用 4/8/12/16/24/32/48/64px。封面圆角 12px、输入 8px、主按钮 8px、状态胶囊全圆；页面没有大面积投影、渐变和自动动画。按钮最小高度 44px，focus outline 2px，正文左对齐。

替代方案：整站沿用旧有窄文本布局很省改动，但列表缺封面、价格与技术字段同权；普通商城模板需要购物车和购买按钮，超出产品边界。选择商品册布局，保留 Agent 完成操作的事实。

### 2. 首页 `/`：店铺 → 商品 banner → 查看更多 → 分步使用介绍

```text
┌──────────────────────────────────────────────────┐
│ 店铺 logo / 店名 / 已发布 summary / 可选地址        │
├──────────────────────────────────────────────────┤
│ 已上架商品                                 上/下张 │
│ [商品名 / 价格 / 库存 | 大封面] [下一商品 banner]    │
│                       查看更多 → /products         │
├──────────────────────────────────────────────────┤
│ 如何使用 MercLink                                 │
│ [我是买家，想购买] [我是店主，想上架]               │
│ 1 交给 Agent → 2 描述需求 → 3 授权 → 4 确认与付款  │
│ 或：1 交给 Agent → 2 批准 → 3 商品资料 → 4 上架     │
├──────────────────────────────────────────────────┤
│ 既定 slogan / explanation / API / 发现文件          │
└──────────────────────────────────────────────────┘
```

- 店铺介绍只用 `model.store` 的已发布字段，仍在最前。无 logo、地址、网站时省略相应内容。无店铺资料则直接从商品开始，不使用示例店名兜底。
- 商品 banner 不是广告系统。直接用 seam 当前页返回的商品、封面、标题、`offer.price` 和库存事实，顺序不变，不增加手工精选、促销文案、独立 banner 字段或后台配置。
- 桌面同时展示约两张宽幅 banner：一侧标题、金额、库存和“查看详情”，另一侧商品图，比例约 2:1。手机一张并露出下一张，文字与图并列且能换行，标题优先。整个横幅链接到对应商品详情。
- 沿用 CSS overflow/scroll-snap 与滚动条，提供 44px 上一张/下一张按钮，触控可滑动、键盘能进入商品链接。按一次移动一张，不自动轮播；无脚本依然横向可滚动。没有商品时显示明确空状态，不展示假 banner。
- banner 下方独立放“查看更多”，作为普通 `/products` 链接，明确进入完整商品列表；即使当前页没有商品，链接也仍然有效，不据数组长度推断商品总数。
- 接着展示“如何使用 MercLink”，买家与店主两个切换入口。桌面每组四步横排，手机每步纵向；使用真正的 `<ol>` 表达顺序。脚本只切换展示，`aria-selected/aria-controls` 与键盘左右键、Home/End 对齐；无脚本两组步骤都显示。

买家四步：

1. **把买家 Skill 交给 Agent**：提供正式站点 `/skill.md`，本步提供地址、复制和查看文档。
2. **告诉 Agent 购买需求**：例如“找一款桌灯，预算 200 元”，Agent 查询公开商品和规格，查商品无需登录。
3. **下单前登录并批准**：按 Agent 给出的设备码地址在自己的浏览器验证或注册买家账号，再批准；密码和验证码只留在浏览器。
4. **确认商品，完成付款**：确认规格、数量，再打开支付宝收银台付款；付款后让 Agent 查询订单，确认已支付，不能将打开付款链接当成功。

店主四步：

1. **把商家 Skill 交给 Agent**：提供正式站点 `/merchant/skill.md`，本步提供地址、复制和查看文档。
2. **店主登录并批准**：使用启动时的店主账号，首次登录先改密码，然后批准商家 Agent。
3. **提供商品资料**：商品名称、售价、库存、图片及属性；有颜色、尺码时说明实际出售的组合。
4. **检查并上架**：Agent 选目录、补必填字段、建可售规格、上传封面并调用 publish；成功后商品出现在店铺首页和列表，失败仍下架。

- 切换两组指引不会跳到授权页、创建订单或发送请求；只是帮助读者理解角色流程。
- 平台名与 Skill 地址在使用步骤中展示，符合本次规格增量。页脚简化为既定 slogan、explanation、API 根地址、llms.txt 和 sitemap.xml，避免重复两套接入说明。
- 复制使用站点公开基址生成的绝对 Skill URL。剪贴板真正写入后才提示成功；失败给出可选中文本；无脚本普通链接仍可用。

### 3. 商品列表 `/products`：封面网格与普通分页

列表页用 `MercLink` 站点导航、返回首页、标题“已上架商品”、一句事实说明和商品网格。每项仍是封面、标题、价格和库存，不添加销量、评分、折扣和不在数据里的目录名称。

桌面 4 列，768–1023px 为 2 列，窄屏 1 列。商品量大时显示 `nextCursor` 的普通下一页链接；不做无限滚动。当前页面只支持游标，本次不放无法接通的搜索框、分类 chips 或价格过滤器。

没有商品时显示“暂无可展示的商品。商品上架后会出现在这里。”并提供返回首页的链接；真实查询失败应显示失败和重试入口，不能将异常吞掉伪装成空列表。未注册 seam 的空列表行为仍按原规格保留。

### 4. 商品详情 `/products/{id}`：先商品事实，再 Agent 辅助信息

```text
返回商品列表
┌─────────────────────┬────────────────────────────┐
│ 商品封面 1:1         │ 商品名 / 价格 / 库存       │
│ 无图有文字占位       │ 全部可售规格及各自金额库存 │
│                     │ 复制购买需求 / 买家 Skill  │
├─────────────────────┴────────────────────────────┤
│ 公开字段             │ 商品 ID / 目录 ID / SKU    │
│ 原始 key + 格式化值  │ 可展开的结构化商品信息     │
└──────────────────────────────────────────────────┘
```

- 桌面为封面与信息两列，手机按标题、封面、价格、规格、辅助动作、属性的阅读顺序单列排列。全页只有一个 h1。
- 主价格直接使用 `offer.price`，规格价格使用各自 `variant.price`。CNY 显示 `¥159.00`；非 CNY 使用对应货币代码/符号，不写死人民币。不改变 JSON 或业务计算中的整数分。
- 所有可售规格从 `product.variants` 显示，不自动生成笛卡尔组合。每行含 optionValues、价格、库存、SKU 和规格 ID。`stock=null` 显示“不限库存”，`stock=0` 显示“缺货”；库存和可售状态不能混为一谈。
- 可以用单选控件高亮某条规格，供复制辅助文本；选中只影响本页信息，不创建订单或锁定库存。缺货仍显示，不作为可复制购买需求的可用规格。脚本关闭时所有规格信息照常可读。
- “复制购买需求”文本包含商品 ID、选定规格 ID，以及“请先查询当前价格和库存，向我确认后再购买”，不把页面显示的价格作为下单入参。只有唯一可售规格时可省略选择；有多条时要求明确选定。页面不放“立即支付”或虚构支付成功反馈。
- `fields` 原样保留当前 key，不建立硬编码翻译表：目前 model 没有字段显示名。布尔值显示“是/否”、null 显示“未填写”，文本保留纯文本，不解释成 HTML。样稿同样使用 `material`、`weight_g` 等 key。将来要显示中文字段名需单独规划 schema 数据接入。
- 技术信息以 `<details>` 展开，重用已有 JSON-LD，保留商品 ID 等可读文本；展开 JSON 与 seam 值一致。不是给页面发明新的 API 响应外壳。
- 下架、软删除、无可售规格或未知 ID 继续走已有 404/noindex 路径，不在错误页残留价格或规格。

### 5. 授权与账号：一个人工确认面板

授权页用宽度约 480px 的面板，左右留白，顶部品牌、步骤标题、用途、表单和底部说明。品牌显示 MercLink；授权面板独立于首页的商品展示与分步介绍布局。

| 页面/阶段 | 展示与交互 | 实现边界 |
| --- | --- | --- |
| `/authorize/device` | 一个完整短码输入；提示核对 Agent 短码；继续按钮 | 原 `user_code` 表单 POST 到 `/oauth/device`；不另建分段输入和前端轮询 |
| 买家 phone | 手机号 + 真实验证码区域；“完成验证并发送验证码” | 保留 BuyerCaptcha 与禁用按钮；未过人机验证不能发短信 |
| 买家 code | 短信验证码，提示发给哪个手机号，允许换手机号 | 使用现有 `intent=check`；发送频率由服务器处理 |
| 买家 password | 已有账号输入密码；新账号设置密码及可选邮箱 | 依照 `mode`，不能把邮箱当登录标识 |
| 买家 approve | 当前账号、可下单/查看自己订单的角色说明、批准按钮 | 仅有 `pendingApproval` 时显示批准；无待授权显示从 Agent 重新发起说明 |
| 商家未登录 | 店主手机号和密码，说明使用启动账号 | 无注册入口；未知手机号沿用店主手机号提示 |
| 商家首次改密 | 明确“先修改初始密码”；改密表单 | UI 禁用/隐藏批准动作；后端 `password_change_required` 仍是最终校验 |
| 商家批准 | 当前店主、可管理目录/商品/查看订单的角色能力说明 | 不伪造 Agent 名称或具体申请 scope；当前 view 没有这类元数据 |
| `/admin` | 店主登录或当前密码/新密码和“修改密码” | 无商品、订单统计、用户开通操作 |
| `/authorize/account` | 已登录脚本的 Key 前缀/状态/撤销及仅显示一次的新 Key | 不带到 Agent 授权步骤；完整秘密不写日志、URL 复制或样稿 |

步骤指示是现有流程的解释，当前实际阶段以服务端 props 为准。匿名页不能预示“已授权”。拒绝授权能力若现有路由未暴露就不增加假按钮；可使用现有退出登录动作或说明关闭页面可停止本次确认。

店主上架指引要明确：先把正式站点 `/merchant/skill.md` 交给 Agent，自己在浏览器登录、首次改密并批准，然后向 Agent 提供商品名、售价、库存、图片及属性。Agent 读取目录和字段，创建默认规格或声明规格轴并创建实际组合，上传封面，再调用现有 `POST /api/v1/catalogs/{id}/products/{product_id}/publish`。创建商品默认下架；必填字段不齐或没有可售规格时，上架失败且保持下架。上架成功后公开查询和页面才展示。人工指引可以出现在店主页面的说明区；首页按商品 banner 后的分步使用介绍展示这些指引。样稿已经给出“上架桌灯，159 元，库存 24 件”的自然语言例子，不要求用户自己换算整数分或调用 API。

错误消息使用现有 `notice`，靠近表单、`role=alert`；仅在服务端已提供具体字段错误时绑定 `aria-describedby`，不靠解析中文消息推测字段。成功只在服务端确认后呈现“已完成，请返回 Agent 继续”。不能根据按钮点击或跳转推出授权完成，更不能把打开支付链接当成已支付。

替代方案：复杂多段 OTP、前端 SPA 状态机和自动倒计时都容易偏离现有流程。保留普通 form POST、原 input name 和 intent，少量渐进增强只用于复制、输入可见性和反馈。

### 6. 工程落地与依赖方向

已阅读当前安装版本的 Next.js 本地 CSS、Server/Client Components 指南。后续 apply 开始时仍需复核相关指南，遵循本项目实际 API。

| 文件 | 后续怎么做 |
| --- | --- |
| `src/app/globals.css` | 只放带 `--ml-` 前缀的设计变量、body 基础、focus；不放裸 `button/label/ul` 的业务页面规则 |
| `src/public-discovery/views.tsx` | 调整现有 Shell/StoreHeader/ProductShelf/ProductSection/ProductView；ProductShelf 增加 banner 呈现，新增纯展示 PlatformUsageGuide，共用商品事实，不新增读取逻辑 |
| `src/public-discovery/public.module.css`（建议新增） | CSS Module 隔离公开页面；替代该文件里的两大内联 CSS 字符串，保持主题一致 |
| `src/public-discovery/interactions.tsx`（必要时） | 小范围 Client Component：Skill 复制、两组使用指引切换、需求复制和规格高亮；主要商品正文继续由 Server Component 输出 |
| `src/public-discovery/model.ts`、`site.ts` | 默认保持查询与元数据行为；公开地址复用现有 `absoluteUrl/publicBaseUrl`，价格只在呈现层格式化 |
| `src/app/authorize/views.tsx` 和 `authorize.css` | 局部 `ml-auth` 根类，统一表单与通知；保留 props、提交路径、input name 与 intent |
| `src/app/authorize/device/page.tsx`、`src/app/admin/page.tsx` | 复用授权样式与信息层级；不把账号操作扩展成后台 |
| `src/app/authorize/buyer-captcha.tsx` | 保持真实验证码与服务端核验链路，确认窄屏容器不溢出；不以 CSS 或本地状态绕过验证码 |

不把整页标为 `use client`，也不从页面直接调用领域模块或数据库。新的 Client Component 只收展示所需的公开值，不收令牌、验证码、私钥或账号密码。其他授权库生成的设备码确认页若不使用这里的 React views，需在 apply 时针对 provider 配置确认实际可定制边界，不修改 OAuth 内部协议。

### 7. HTML 样稿与交付方式

`preview/index.html` 为一个无构建步骤的自包含文件，CSS、示例 SVG 和 JS 内联，无 CDN、远程字体、真实 API 请求、localStorage 或生产账号数据。

顶部明确标注“设计预览 · 示例数据”，提供首页、列表、详情、买家授权、店主、脚本账号六种视图，及一个“状态”选择器。工具栏是预览器，不属于部署网页。通过 hash 切换视图，直接打开 `#detail` 可定位详情。首页 banner 滚动、查看更多跳转、买家/店主步骤切换、规格选择、复制辅助文本、演示授权各阶段都能点击查看。授权样稿使用固定文字和按钮切换，不输入、不收集用户真实手机号、验证码或密码；每一次结果都写“演示”，不充当真实授权。

关闭脚本时样稿顺序显示所有视图，仍能读到首页店铺、商品和页脚。生产实现保持真实 SSR 和原表单提交；样稿的 hash 导航不会替换 Next.js 路由。

### 8. 响应式、可访问性与状态矩阵

验收尺寸至少为 1440×1000、768×1024、390×844、320×740；以内容折行为依据微调断点，不按 User-Agent 判断设备。除明确的横向货架/规格长 ID 区域外，页面不能出现整体横向滚动。付款渠道不受样稿设备尺寸影响。

| 状态 | 人看到什么 | 下一步 |
| --- | --- | --- |
| 店铺资料未发布 | 不显示介绍块，正常显示商品 | 看商品、到页脚读 Skill |
| 无商品 | 清晰的暂无商品文字 | 列表返回首页；不显示虚构推荐 |
| 无封面 / 图片失败 | 等比例占位与“暂无图片” | 仍可读标题和价格、打开详情 |
| 缺货 | “缺货”文字；对应规格不能复制购买需求 | 查看其他规格，或返回列表 |
| `stock=null` | “不限库存” | 正常阅读，不显示错误的库存 0 |
| 商品不可公开 | 404/noindex 与返回列表 | 选择其他商品 |
| 验证码/依赖失败 | 服务端现有消息，允许重新验证 | 不发短信，不切到成功阶段 |

## Risks / Trade-offs

- [原规格规定平台入口只能在页脚] → 本变更根据用户要求完整修改首页入口及货架要求；先交付方案和样稿，apply 后再同步主规格。暖纸/绿色风格继续保留。
- [示例商品容易被误认为真实] → 工具栏、页脚和 README 标注示例，附件独立放在变更内，生产不引用 fixture。
- [字段显示名目前缺失] → 第一版保留真实 key；不臆造中文标签，也不新增并行 schema。
- [有可售规格但部分缺货] → 详情逐条显示，不将可售状态当作库存；不从 UI 移除事实。
- [样稿授权比真实流程简化] → 明确标为演示，实施继续用现有 POST、验证码和服务端阶段；不照抄演示 JS。
- [OAuth provider 生成的页面未必复用 React views] → 只承诺自有页面的统一样式，核实 provider 可配置的 HTML/错误页面后再适配。
- [内联 CSS 分离涉及现有页面 HTML 断言] → 只更新因呈现变化失效的断言，保留 SSR、store 顺序、可见范围和 JSON-LD 断言。
- [全局选择器互相覆盖] → 公开页使用 CSS Module，授权根类局部化；本次不顺手改其他业务代码。
- [系统衬线字体在不同平台略有差异] → 容许字形差异，用固定字号/行高/容器控制阅读层级；无需字体 CDN。

## Migration Plan

本轮已明确 apply，只改前端，不需要数据库迁移。按“基础样式 → 公开页 → 授权页 → 校验”实施，不改数据库。

1. 复核本地 Next.js 指南；先落实 token 和样式隔离。
2. 改首页及共用商品卡，再改列表和详情；保证禁用 JS 仍有正文、链接和 JSON-LD。
3. 接入少量复制和规格辅助交互，再统一现有授权及改密表单。
4. 更新受影响的 public-discovery/identity 渲染断言；跑类型、边界和全量 check，再做桌面/手机、键盘、无脚本截图验证。
5. 普通代码部署即可；回退该前端提交恢复旧呈现，业务表和付款记录不需回滚。
