## Why

项目已经具备单店公开展示、商品查询、设备码授权和店主改密能力，但首页、列表、详情和授权页使用分散的样式，列表与详情仍直接展示“分”和技术字段，读者难以迅速理解商品与下一步操作。需要在现有产品边界内建立统一的展示和交互规则，并先用独立 HTML 样稿验证视觉方向。

## What Changes

- 首页改为“店铺介绍 → 可手动滚动的商品 banner → 查看更多进入商品列表 → 平台分步使用介绍 → 简洁页脚”，保留暖纸色、衬线店名和绿色强调色。
- 统一公开页面的排版、间距、商品封面、人民币金额、库存文字、无图和空列表状态；商品详情完整显示公开属性和可售规格。
- 在商品 banner 下方按步骤解释买家与店主如何使用平台；两种角色可切换，支持复制对应 Skill 地址。详情提供复制商品或规格信息的辅助动作，购买仍由买家 Agent 完成。
- 为设备码、买家登录/注册/批准、商家登录/首次改密/批准、脚本账号页和店主改密页定义一致的表单、错误和成功反馈。
- 交付可离线打开的多页面 HTML 设计样稿，使用明确标注的示例数据；样稿只演示页面和交互，不连接生产 API。

## Capabilities

### New Capabilities

- `frontend-presentation`: 现有人工授权和账号页面的视觉、可访问性、状态提示，以及设计样稿的隔离要求。

### Modified Capabilities

- `public-pages`: 将首页横向货架调整为商品 banner，并允许商品列表入口及平台分步介绍出现在 banner 后的主体区域；增加统一展示、金额与库存呈现、详情层级、响应式和渐进增强要求，保留店铺优先、SSR 和发现文件约束。

## Impact

后续实施涉及 `src/public-discovery/views.tsx`、必要的公开页面样式、`src/app/globals.css`、`src/app/authorize/views.tsx`、`src/app/authorize/authorize.css` 和 `src/app/admin/page.tsx`。复用 `src/public-discovery/model.ts`、公开商品与店铺 seam、现有授权提交路由及验证码组件，不新增 API、数据库字段、依赖或业务模块。

方案与独立 HTML 已交付。本轮根据用户明确授权实施前端页面与交互，复用既有服务端查询和表单接口；后端 API、应用服务、领域、数据库及主规格不改。

非目标：商品管理后台、手工编辑店铺资料、购物车、直接网页下单、订单中心、营销推荐、第二家店、支付回跳页，以及改变认证、短信、限流和支付规则。

命名兼容说明：本机 OpenSpec CLI 拒绝数字开头的变更名，因此采用可执行的 `frontend-experience-design` 目录名；日期为 2026-10-09，记录在变更元数据及附件说明中。既有日期前缀变更不作调整。
