# Design

## 为什么这样写

Skill 已经禁止把令牌贴进对话，也写了已登录接口使用 Bearer。Agent 遵守了前一句，却把令牌只留在当次 shell 变量里。下一轮查单没有头，`40100` 的「需要登录。」又被理解成授权失效。

接口不区分“没带头”和“凭证被拒绝”，都是 `40100`。Skill 也不能让 Agent 根据 `message` 分支。能判断的是 Agent 自己这次有没有带保存的令牌。

## 决定

- 换到令牌后，访问令牌和刷新令牌都由 Agent 自己保存。不出现示例值。
- `POST /api/v1/orders` 和 `GET /api/v1/orders/{id}` 使用同一个访问令牌。
- 刷新请求写清 `grant_type=refresh_token`、原来的 `client_id` 和保存的刷新令牌。旧刷新令牌失效后保存新的一对。
- 只有保存的访问令牌和刷新令牌都没有时，才重新申请设备码。
- 不改商家 Skill。商家文档已经单独写了刷新请求；这次只修买家查单丢令牌。

## 不做什么

- 不新增公开查单接口，也不放宽买家订单的登录要求。
- 不把 `40100` 拆成两个错误码。
- 不在 Skill 里放令牌示例值。
