# Design

## Context

见 `proposal.md`。店铺介绍是 `merchant_profiles` 上的整份替换，公开读取在介绍未发布时返回 `404`。商品上架是另一条状态。公开商品详情走 public-product seam，列表和详情共用商品可见性。店面槽位由已发布模板声明，服务端只填已声明的槽，并去掉商家自己的 `application/ld+json`。

介绍正文的纯文本规则在 `src/domain/identity/profile.ts`：控制字符被去掉后再量 `Array.from(value).length`，HTML 和 Markdown 用同一套 `markupPattern`。问答规格要求换行直接拒绝，而不是悄悄删掉。

## Goals / Non-Goals

**Goals:**

- 全店问答和商品问答各是一行记录，发布标志与介绍、商品上架互不影响。
- 公开页、Markdown、公开 JSON 和 `FAQPage` 使用同一次读到的已公开条目。

**Non-Goals:**

- 不把问答放进 `merchant_profiles` 或 `products` 的列，也不写入目录 `fields`。
- 不新增公开 FAQ 路径、错误码、scope 或依赖。
- 不把全店问答自动附到每件商品上，不预置问题，不参与关键词搜索。
- 不改「如何使用 MercLink」。

## Decisions

1. 新表 `merchant_faqs`。一行是一个商家的全店问答，或一件商品的问答。`product_id` 为空表示全店；非空表示商品，并外键到该商品。`published` 布尔，`items` 为 JSON 数组，元素只有 `question` 和 `answer`。全店用部分唯一索引保证每个商家一行；商品用 `product_id` 唯一。软删除商品不删这一行。
   另加列到介绍或商品上会让那两次整份写入碰到问答。独立表才能让 `PUT` 只替换问答。

2. 校验放在 `src/domain/identity/faqs.ts`，不读取数据库。先拒绝换行、HTML 和 Markdown，再去掉首尾空白，用 `Array.from` 量长度。问题 1 到 80，答案 1 到 400。全店最多 12 条，商品最多 8 条。同一份里问题去空白后相同则拒绝。`published: true` 且条目为空则拒绝，且不写库。登录手机号和账号邮箱沿用介绍的包含判断。调用方传入密钥，领域层不查库。
   复用介绍里未导出的正则会让身份模块互相依赖内部函数。问答解析自己保留同样的标记规则。

3. 应用服务一个用例文件，两条路由都调用它。`GET` 没有行时返回空草稿，不插入。`PUT` 整份替换。商品路径先确认目录拥有该商品且商品未软删除，否则 `404`。买家或缺少 `product:write` 为 `403`。介绍 `PUT` 和商品创建、`PATCH` 遇到 `faqs` 仍走现有未知字段拒绝。
   不把问答并进商品 `PATCH`，否则省略和清空又要定义一套与规格不同的语义。

4. 公开店铺路由同时读介绍和全店问答。介绍已发布时，现有字段不变，并加上 `faqs`；未公开或没有条目时 `faqs` 为 `[]`。介绍未公开但全店问答已公开且非空时，响应 `200`，JSON 只有 `faqs`。两者都不可见，或商家已停用、已删除时，仍是 `404`。
   公开商品详情在现有 seam 的单件结果上附加 `faqs`。未公开的问答不进入 seam。列表查询不查、不返回 `faqs`。这样详情和页面仍是一次商品读取，不是第二套商品内容。

5. 内置首页的顺序是店头、商品货架、全店问答、联系方式和执照、使用指南。问答紧接货架，不插到联系方式后面。内置商品页把用户 Skill 链接留在商品信息下面。商品问答在详情正文之后横跨整栏，不放进右侧描述栏。正文到商品信息为止，包括名称、价格、描述和规格。问题用 `h3`，答案用转义后的段落。没有可见条目时不输出这块。`/index.md` 和 `/products/{id}.md` 用同一份条目；空则省略该节。
   有可见条目时另加一段 `FAQPage` JSON-LD，不改现有 `OnlineStore` 或 `Product` 文档的根类型。两段脚本都由服务端写入。

6. 店面增加重复区域 `data-merclink="store.faq"` 和 `data-merclink="product.faq"`。区域内只许 `faq.question` 和 `faq.answer`。区域外出现这两个槽位则模板无效。已发布模板没有对应区域时不改写发布物，页面也不补问答。起始模板和内置页都声明这两个区域。

未激活时内置 HTML 把已公开问答放在独立区域里：有条目时标题是一个 `h2`「常见问题」，每题一行，同一页同时只展开一条：默认全部收起，打开另一条时收起前一条，不依赖脚本；答案仍在同一条 HTML 里。没有条目则整块不出现。`/index.md` 和 `/products/{id}.md` 在有条目时仍用 `## 常见问题`。已激活且模板声明了对应区域时，有可见条目就在该区域条目前恰好插入一个 `<h2>常见问题</h2>`，空集则去掉区域且不留标题；起始模板源码不写死这个标题。`FAQPage` 仍由服务端单独注入，问答文字与可见条目一致。商品令牌先替换模板骨架，再展开问答，已插入的问答原文不再被改写。

## Risks / Trade-offs

- [调用方把 `GET /api/v1/store` 的 `200` 当成介绍已发布] → 这是提案里的破坏性变更。只有问答公开时响应不含介绍字段。文档和商家 Skill 写明这一点。
- [后归档商品描述或字段显示名] → 那两份未归档变更也改商品页规格。本变更的商品页增量是新增 Requirement，不替换「Product pages use the public query seam」。归档时仍不得用旧正文覆盖另一份对同一条 Requirement 的修改。
- [自定义店面看不到问答] → 槽位合同如此。商家在模板里声明区域后重新激活。公开 JSON 和 Markdown 不依赖该模板。
- [停用商家后问答仍被公开] → 公开读取和介绍一样，商家停用或删除时不返回问答。

## Migration Plan

追加 `src/db/migrations/018_merchant_faqs.sql`，不改已应用的迁移。

1. 创建 `merchant_faqs`，含商家、可空商品、`published`、`items` 和 `updated_at`。
2. 加上全店部分唯一索引和商品唯一约束。不回填，不预置问题。

回滚时删除这张表。回滚前写入的问答会丢失；介绍、商品、订单和支付不依赖它。

部署后公开行为与现在一致，直到商家公开一份非空问答。
