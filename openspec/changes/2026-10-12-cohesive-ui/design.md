## Context

用户批准了审查方案并要求本轮先文档后实施。现有默认页面与下载模板共享 `views.tsx`；后者不运行 React 客户端。现有深暖色和影片带改动保留。CLI 校验使用 `cohesive-ui`（本机拒绝数字开头的名称），通过后目录改为项目约定的 `2026-10-12-cohesive-ui`。后续 CLI 操作需注意这个本机命名限制。

## Goals / Non-Goals

**Goals:** 完整图片首屏、可读长正文、一致的操作反馈、手机适配、无脚本事实可读。记录 `docs/UI.md`，作为后续界面工作的依据。

**Non-Goals:** 不引入新 UI/动画库、字体下载、生成图片、购物车、搜索筛选、推荐、支付或授权新协议。无需新增后台。

## Decisions

1. 沿用深暖墨、象牙和黄铜，整合语义 token。系统字体继续使用现有衬线与无衬线组合；表现力来自真实照片、比例和空间，不增加粒子或持续缩放。
2. 详情桌面左图右信息，手机先图后信息。已有 `price_unit` 字段可靠近价格；任意长文本字段采用宽幅段落，所有公开字段继续展示。图集用原生单选控件切换，键盘和无脚本都可用；无图时保留占位。
3. 影片带使用 CSS，桌面两组等宽内容无缝循环，悬停/聚焦/勾选暂停停止；触摸屏、窄屏及减少动态效果模式停用动画和重复内容，原生滚动可用。下载模板缺少复制组时保持静态横滑，不伪造失效控制。
4. `slotHtml` 已输出安全 HTML，React 包装层不再把它当未转义字符串再次输出。用恶意标题与字符引用回归测试确保显示保真且保持转义，不能直接插入未经处理的商品字段。
5. 列表保持原分页。文档使用独立阅读排版与可折叠目录；授权页只调整视觉、步骤语义和准确文案，不改提交地址/隐藏字段/验证顺序。
6. 默认下载模板使用相同布局、viewport 和设计 token，保持槽位协议。完整图集增强仅在已有结构化事实可用时显示；模板通过现有 cover/field/variant 槽位保留完整事实及原生导航。

## Risks / Trade-offs

- 全局样式影响导出模板 → 沿用 page/ml-auth 作用域，增加模板实际填充后的回归覆盖。
- 长商品名和任意字段 → 不截断详情标题；短字段和长字段采用不同布局，移动端单列。
- 首图影响加载速度 → 首屏封面 eager，其余 lazy；维持已配置的媒体来源。
- UI 技能的通用购物车/游客结账与 PRD 冲突 → 按项目范围只采用适用的视觉方法。
- 旧规格要求所有终端自动横移 → 本增量明确限定桌面自动，手机手动，并同步文档，不静默更改。

## Migration Plan

先完成文档与规格，再改共享模板和样式，再补测试、运行检查与冒烟，最后浏览器核对桌面/手机及交互。无数据库迁移，不激活店面、不提交代码。

## Open Questions

无；采用用户已确认的设计方向。完整冒烟依赖独立 `merclink_smoke` 进程；缺失时记录限制并运行覆盖清单检查。
