# 店面重置只在同一事务成功后记为已执行

## 为什么

`POST /api/v1/storefront/reset` 只应创建待批准请求。执行时如果对象删除失败仍清空发布，或状态更新没有写上却返回已执行，线上指针会和对象存储不一致。Agent 也不能自己批准这次删除。

## 做什么

- 创建重置请求不删除发布，也不改指针。
- 只有已登录的管理员会话能执行一条 `pending` 请求。Agent 令牌不能执行，也不新增 Agent 执行路由。
- 任一对象删除失败就返回错误，不改数据库，请求保持 `pending`。
- 删除成功后，在同一 SQL 事务里清空指针、删除发布行，并把该 `pending` 行标为 `executed`。
- 状态更新影响 0 行时回滚该事务，不返回成功。
- 成功响应表示状态已是 `executed`，且指针不再指向被删除的发布。

## 不做什么

- 不让创建请求顺带删除。
- 不新增错误码、表或依赖。
- 不改支付、授权或上传激活。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `storefront-release`：重置执行的失败和提交语义。

## Impact

店面重置应用服务和 SQL 存储。不改已有迁移。
