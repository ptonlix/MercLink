# Proposal

## Why

现在的落地页把项目说成「让 Agent 查询已上架商品并下单」。这只是机制，不是目标。目标是在 AI 时代帮中小商家做自己的店，并把这个店接到 Codex 等 Agent。页面却把接入链接放在最上面，还写了「商家不能自助注册」。那句话是管理规则，不是访客要看的内容。

## What Changes

- 这个部署的公开站就是一家店，不是商家目录。不新增 `/merchants` 或 `/merchants/{id}`。
- 商家 Agent 维护这一家店的公开资料：展示名、一段纯文本简介、可选网站、可选标识、可选服务区域和可选公开地址。不是每本目录一份，也不使用目录自定义字段或 HTML。
- 商家 Agent 用已有商家令牌读取、保存、发布或撤回。未发布时，落地页不显示这份介绍。超管开通时填写的账号名不会自动公开。
- `/` 开头只展示这家店：店名、简介、有值才显示的标识、服务区域、地址和网站，然后是已上架商品。店名是页面主标题。
- MercLink、Slogan「在 AI 时代，让天下没有难做的生意」和解释「帮中小商家做自己的店，并让各种 Agent 直接找到商品、完成购买。」放到页脚。商品列表、两份 Skill、API 根地址和发现文件也在页脚，不占开头。
- 已上架商品用商品卡片横向货架呈现，而不是标题列表。每张卡片包含封面、标题和按元显示的价格，整卡进入商品页。货架可左右移动，不自动轮播。
- 视觉参照 SceneAI 上偏商品陈列的浅色货架，不参照霓虹科技风。只固化我们自己的纸色、衬线和卡片规则，不复制该站的提示词、图片或文案。
- `/` 不再出现「商家不能自助注册」，也不出现「进入这一家的店」。这条开通规则仍只留在商家授权页和商家 Skill。
- 公开 `GET /api/v1/store` 与落地页使用同一份已发布介绍。没有第二家店可列。
- 登录手机号、密码、账号邮箱和未发布草稿不得出现在公开 HTML、JSON-LD 或公开接口。

## Capabilities

### New Capabilities

- `merchant-public-profile`: 商家 Agent 维护这一家店的公开介绍；落地页和公开接口只展示这份已发布资料。

### Modified Capabilities

- `public-pages`: 落地页就是这一家店。介绍和商品在上，接入链接在下，不再写不能自助注册，也不列出多家店。
- `agent-skills`: 商家 Skill 增加资料的读取、保存、发布和撤回，并禁止把登录手机号写成公开联系方式。

## Impact

- 新增商家资料表和迁移。账号表继续只放开通信息，不把公开文案塞进 `merchants`。
- 新增商家 `GET`/`PUT /api/v1/merchant/profile`，以及公开 `GET /api/v1/store`。都登记到路由表和商家 Skill。
- 不新增 OAuth 权限。保存和发布复用已批准的 `product:write`，避免现有商家重新授权。
- 公开读取走新的查询缝，页面不直接读商家表，也不另建一份展示数据。
- 不新增错误码。校验失败用 `validation_error`，无权用 `forbidden`，公开不可见用 `not_found`。
- 不改买家注册、下单、支付、目录字段或商品查询。不增加按商家过滤，也不增加商家目录页。
