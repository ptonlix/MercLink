## Why

接口已覆盖商品展示、商家管理、授权与交易，但“接口存在”尚不能直接转成清晰的页面：公开目录导航、网页交易会话、买家订单列表等能力仍有缺口。需要一份基于现有实现的页面方案，让买家能理解商品、店主能完成 Agent 上架流程，并明确每个界面的数据与操作来源。

日期：2026-10-09。根据用户最新反馈修订：首页在横幅上方明确展示商品数量与“查看全部商品”入口，列表卡片统一大小，长标题省略；使用说明保留在问号弹窗。此轮更新设计与预览附件，不实施应用代码。

## What Changes

- 首页收紧为“店铺介绍 → 商品数量与查看全部商品 → 可滚动商品横幅”，列表入口位于横幅上方，商品链接进入详情。总数须来自真实总数或完整查询结果，不能以不完整的首页商品数冒充。
- 将买家和店主使用说明集中进问号帮助弹窗，默认关闭；移除预览顶部六页工具栏及独立店主指南预览。
- 设计公开商品列表的搜索、目录上下文筛选、游标分页与空状态；商品卡片统一大小、封面 4:3、标题固定两行并省略超出文本，详情保留完整名称。公开接口没有目录列表，不虚构完整分类导航。
- 设计商品详情的图文层级、Schema 标签、规格选择、数量及“复制给 Agent”购买指令，使用真实价格和库存，不加入未经支持的日期预约。
- 在帮助弹窗设计店主指南与买家/商家授权说明，解释登录、改密、批准之间的关系。商品与订单管理仍由 Agent 调用现有 API，`/admin` 保持登录与改密职责。
- 提供三页浏览链路、问号弹窗、页面与接口映射、响应式规则、实现顺序和独立 HTML 方案预览；明确当前单店部署与未来同平台多商家的区别。
- 单独列出人工商品后台、网页直接下单、订单中心的后续扩展条件，不纳入本变更实施范围。

## Capabilities

### New Capabilities

- `frontend-page-journeys`: 基于现有接口的浏览、商品理解、Agent 购买协助、店主使用引导与授权反馈；包含数据缺失、无库存、失败和手机端展示规则。

### Modified Capabilities

- `public-pages`: 首页主体只保留店铺与商品浏览链路；帮助入口显示为问号，使用说明默认隐藏在弹窗中。此处基于用户最新要求替代前一提案的正文使用步骤，实施前需处理两份增量的顺序。

## Impact

- 未来实现涉及 `src/public-discovery/model.ts`、`views.tsx`、`interactions.tsx`、`presentation.ts`、`public.module.css` 和 `src/app/products/page.tsx`。帮助内容复用现有角色说明，不新增 `/merchant/start` 页面。目录 Schema 使用现有应用层读取能力，不建立第二套商品查询。
- 授权展示沿用 `src/app/authorize/**` 的现有服务端流程及表单字段；不更改 Cookie、scope、客户端注册或设备码协议。
- 后端路径、数据形状、数据库、依赖、库存与支付规则均不变。
- `/api/v1/store` 未发布、缺少公开目录列表、API Key Cookie Path、OAuth 本地地址混用、搜索 PRD/规格差异作为已知限制记录；不在设计阶段悄悄修复。
- 受 PRD 约束，人工商品管理后台和网页收银台必须作为后续独立范围讨论，不能因 API 能力存在而自动实施。
