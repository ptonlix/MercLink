## Context

日期：2026-10-09，按用户最新界面反馈修订。面向已经运行的 MercLink 单店项目，依据 [接口指南](../../../docs/FRONTEND_API_GUIDE.md)、PRD、架构、主规格和实际页面编写。此文件是前端方案；附带 HTML 仅演示布局，不调用业务接口。

现有页面已经有首页横幅、商品网格、详情规格选择、分角色使用说明和授权表单。用户反馈首页层次混乱，因此先将主页收紧为店铺介绍、商品数量与列表入口、商品横幅，并将使用步骤迁入问号弹窗。其余方案继续解决原始字段 key、列表搜索缺失、登录与授权混淆、行程文字与日期预约混淆的问题。

当前产品由 Agent 完成管理和交易。PRD 第 3 节明确写着“不把商品管理做成人点的后台”，`/admin` 只改密码。因此，方案分为可在现有产品内实现的页面，以及需要另立范围的后续扩展。不能因为 CRUD 或下单 API 已存在，就直接增加网页后台或收银台。

上一轮 `frontend-experience-design` 已实现但未归档，原先在首页正文放使用步骤。用户最新要求将其收进问号帮助弹窗，并去掉多页预览工具栏；本次以最新要求为准更新方案及 public-pages 增量。正式 apply 时先处理前一增量的同步顺序，不能将旧正文步骤再次覆盖到新版首页。

## Goals / Non-Goals

**Goals:**

- 买家进入页面能迅速理解卖什么、多少钱、有什么规格、怎样让 Agent 购买。
- 店主能找到管理 Skill，理解“准备资料 → 发起授权 → 登录并批准 → Agent 创建和上架 → 公开检查”的完整流程。
- 页面展示使用现有接口事实，字段缺失、库存不足、未发布店铺、授权过期均有明确表现。
- 页面从设计到实现有可执行的布局、交互、接口映射、状态和验收条件。

**Non-Goals:**

本变更不实施人工商品后台、网页直接下单、买家订单中心、店铺装修、推荐排序、相册后台、日期预约、小费结算、退款、购物车、商家注册或第二套授权。不会修改后端、数据形状、数据库或依赖。

## Decisions

### 1. 信息架构：三页浏览链路，问号集中说明

```text
店铺首页 /：店铺介绍 → 商品数量与“查看全部商品” → 商品横幅
                         │           └→ 商品列表 /products
                         └─────────────→ 商品详情 /products/{id}
商品列表：返回首页、搜索、商品卡片 → 商品详情
商品详情：返回列表、图片、价格/规格/数量、商品介绍

每页右上角 [?] → 帮助弹窗（默认关闭）
  ├─ 我是买家：Skill → 确认商品 → 登录并批准 → 付款后由 Agent 查状态
  └─ 我是店主：Skill → 提供资料 → 浏览器批准 → Agent 配置及上架

授权入口仍由 Agent 给出设备码确认链接。
密码维护 /admin；脚本账号 /authorize/account 为独立既有功能。
```

首页主体只有三块。帮助说明不占首页正文，不再新增 /merchant/start 指南页。预览也只保留首页、列表、详情，移除顶部方案切页工具、技术提示和独立授权演示。平台发现链接可在正式页脚折叠收纳。

列表/详情使用简短返回链接和问号，避免重复导航层级。商品详情的“交给 Agent 购买”展开购买请求，不冒充网页直接下单。

### 2. 视觉方向：成都夜游内容，通用商品册外壳

保持现有暖纸色和绿色强调色，记忆点使用用户提供的成都夜景和旅客照片。照片自然呈现夜景颜色，不再增加渐变、装饰光斑或营销指标。

| 项目            | 方案                                                              |
| --------------- | ----------------------------------------------------------------- |
| 背景 / 内容面   | `#F6F4EE` / `#FFFFFF`                                             |
| 正文 / 辅助文字 | `#26332B` / `#60695F`                                             |
| 主操作 / 分割线 | `#4E653E` / `#D8DDD1`                                             |
| 错误提示        | `#A13E30`，同时有文字说明                                         |
| 标题            | `Iowan Old Style`、`Songti SC`、系统 serif；中文正文不强制衬线    |
| 正文            | `Avenir Next`、`PingFang SC`、`Microsoft YaHei`、sans-serif       |
| 字号            | 大标题 48–56，页面标题 32–40，内容标题 24，正文 16，辅助 14px     |
| 宽度 / 间距     | 内容上限 1160px；桌面边距 40，手机 20；间距 8/16/24/32/48/64      |
| 图片 / 控件     | 卡片图片约 4:3；横幅约 16:9；详情保留原图比例；圆角 8–12px        |
| 交互            | 按钮至少 44px，明确 focus；只使用操作触发的滚动和展开；无自动轮播 |

首页在横幅上方设置商品栏：左侧为“店内商品”和真实已知的数量，右侧为“查看全部商品”。入口使用品牌绿色填充、白色文字与 20px 小箭头，点击高度不少于 44px，手机仍与数量并排，让首屏就能识别列表入口。问号继续使用 24px 绿色 SVG 圆环图标，笔画与箭头均为 1.75px，透明底，帮助点击区域保持 44×44px；悬停背景与键盘焦点仍有明确反馈。

风格复核：不用通用商城的评分、原价划线、优惠标签、销量和经营数字，它们没有数据来源。英文长标题在详情自然换行，列表标题固定预留两行，超出显示省略号；短标题也预留相同空间，使卡片等高、价格对齐。详情文章宽度控制在约 70 字符，英文段落留足行距。

### 3. 首页 /：店铺介绍、商品数量与列表入口、商品横幅

```text
店铺名称                                      [?]
店铺简介 / 可选服务区域、网站

店内商品                              [查看全部商品 →]
共 6 件商品
[商品封面 | 商品标题 / 价格 / 查看详情] [下一商品]

小型页脚；完整平台说明默认收进帮助弹窗
```

- 店铺名称与简介在最前，问号位于右上角。线上使用已发布 store 数据；未发布时不虚构店名。预览为表达布局使用明确标注的店铺介绍示例，不写入后端。
- 横幅直接使用实际商品查询事实：封面、标题、价格、库存状态与详情链接。只展示一件商品时隐藏切换按钮；多件时支持手动滚动，不自动播放，不重复同一商品凑轮播。
- “查看全部商品”与商品数量放在横幅上方，点击进入商品列表，点击横幅进入商品详情。无需滚到横幅底部寻找入口。
- 总数只使用权威总数或已穷尽公开分页的完整结果。本次预览快照有完整 6 件商品，因此显示“共 6 件商品”；未加载完整时显示“已展示 N 件”，不把横幅数量当作店内总数。正式接入沿用现有 publicProducts 查询能力，不增加另一套商品查询或后端统计接口。
- 首页不显示角色切换、操作步骤、授权表单、经营指标、JSON 或 API 说明。问号弹窗默认关闭，关闭后不留空模块。
- SSR 继续使用 publicStore/publicProducts；HTML API 能力对应 GET store 与 GET products。无商品与接口故障仍区分为空状态和错误重试。
- Store metadata、JSON-LD 与正文使用同一事实。正式页脚可用原生折叠容器保留 Skill、API 与发现文件，不影响三块主体顺序。

### 4. 商品列表 `/products`：搜索与阅读，而非复杂商城筛选

```text
商品列表
[搜索商品                           ] [搜索]
已输入的条件 [清除筛选]
已知目录时：[价格下限] [价格上限] 币种 [应用]
             [展开本目录支持的字段条件]

[封面]                [封面]                [封面]
标题                  标题                  标题
¥150 / 可购买         价格 / 库存状态         价格 / 库存状态

                       加载更多
```

- 桌面三列，平板两列，手机一列；较宽手机可两列，但价格、标题和触控区域不能被压缩。
- 每张卡片只放一张封面，图片框固定 4:3；CSS 明确覆盖 HTML 固有高度，避免 1080px 源图把卡片拉长。封面为拼图时仍是一张原始资产，不另渲染附图。卡片在同一视口下等宽等高；标题固定预留两行，超出省略，短标题不缩短卡片，价格行位置一致。完整名称保留在可访问文本、鼠标悬停提示和详情页中。
- 搜索用 GET 表单，将 `q` 存入页面 URL；Enter 与搜索按钮一致。首次渲染仍有商品内容，不依赖 JS 才请求首屏。
- 目前页面仅处理 `cursor`，需要扩展 URL/model；商品 seam 已有 q、catalogId、minPrice、maxPrice，继续复用。
- 页脚“加载更多”保留同样条件并传 `next_cursor`；无脚本时为普通下一页链接，JS 可渐进增强为追加列表。条件变化清空游标。完整总数未知时显示“本页 N 件”；已知总数时显示“共 N 件商品”，筛选时分别显示匹配数量与总数。
- **没有公开目录列表接口**，不调用受保护 `GET /api/v1/catalogs` 来生成买家分类。只有 URL 已带 `catalog_id` 或其他合法页面上下文提供目录时，显示该目录的 Schema 条件；无上下文时展示关键词搜索即可。
- 金额筛选在已知目录和币种时展示；跨目录不把不同币种的整数分误称为统一人民币价格。
- 数字字段显示上下限/比较输入，boolean 显示“全部/是/否”，single-select 用 choices。该筛选能力已有 HTTP API，但共享公开 seam 尚无 fieldFilters，需要在既有应用层查询适配中接入，避免第二份过滤规则。
- 筛选无结果显示已用条件与“清除筛选”；非法字段/停用字段提示刷新条件，不默默忽略。
- 搜索文案只叫“搜索商品”。PRD 与生效规格对跨目录 text 匹配的差异需先统一，不在此变更调整实际查询语义。

### 5. 商品详情 `/products/{id}`：图片、可购买信息、内容三层

```text
首页 / 商品列表
Chengdu After Dark: Night Bike, Riverside Market,
Twin Towers & Bamboo Fountain

┌────────────────────────────┬─────────────────────┐
│ 商品封面                   │ ¥150.00             │
│ 原图比例，无硬裁切          │ 可购买              │
│                            │ [选择规格]          │
│ 当前商品已知附图，可展开查看 │ 数量 [-] 1 [+]      │
│                            │ [交给 Agent 购买]   │
└────────────────────────────┴─────────────────────┘

商品介绍（description 的 label）
英文原文，多行分段
行程体验 / 路线亮点 / 参加须知
时间：19:00–21:30     联系方式：eileeness
其他有效自定义字段

[折叠：提供给 Agent 的规格与结构化数据]
```

数据顺序：读取 `GET /api/v1/products/{id}` → 按返回的 `catalog_id` 读取 `GET /api/v1/catalogs/{id}/schema`。商品主体优先展示；Schema 故障时保留商品，并给字段使用可读的保守 key 回退，不让整页报错。

字段展示规则：

- 名称用 Schema `label`，值来自公开商品 `fields`；不把后台技术 key 当主标题。
- text 保留换行，长文按段阅读；number 显示数值，boolean 显示是/否，single-select 显示已选值；全部按纯文本转义，不注入 HTML。
- 旅游商品已有 `description/experience/highlights/good_to_know/schedule/wechat/pricing_model`，可在这个已知目录做轻量阅读映射。未知目录回到标签和值布局；不能认定所有商品有行程或微信。
- 未定义单位不能凭字段名拼接“分钟/人/件”；当前夜游可把已有 `pricing_model` 作为每人价格说明，与后端数值金额分别呈现。
- 公开 API 没有 gallery。当前商品 `photo_2_url/photo_3_url` 是已知文本字段；只在当前映射中将校验过的 http(s) 图片地址用于附图，不把所有 URL 字段自动变相册。其他商品只展示 cover。
- 详情主图按原比例显示，最大高度 420px；附图默认收起，显式隐藏未展开的内容，重新进入详情时恢复收起。展开后每张附图在 140–220px 高的框内完整展示，避免竖图拉长页面，不变形。
- 附图不能加载时显示“图片暂时无法显示”，主信息仍可读；缺少附图时不显示空缩略图。更多相册管理需新接口合同。

规格与购买协助：

- 单一默认规格显示“标准规格”；多规格按 option_values 显示现有组合的可读标签，Schema 缺少规格轴 label 时保留 key。没有公共 axes 定义，不创造不存在的组合。
- 选择后更新该规格 price、stock、availability。最低价只用于尚未选择时的摘要，不能代表每个组合价格。
- 数量为正整数；有限库存时不能超出 stock。规格售罄仍展示并标明，但不能选为购买目标；全售罄时按钮禁用且说明原因。
- 按“交给 Agent 购买”展开可编辑/可复制的指令，而非创建订单。指令包含商品 URL、选中 variant_id、数量、买家 Skill URL，并要求 Agent 先确认总价、完成买家授权，再下单和查询结果。
- 复制不代表下单成功，不显示“预约成功”。剪贴板失败时显示可手动选中的指令文本。
- 不显示日期选择、当晚剩余名额、集合点地图或退款承诺，除非将来有相应可验证字段和业务支持。

### 6. 问号帮助弹窗：按角色介绍使用方法

每个浏览页右上角放一个 44px 问号按钮，aria-label 为“平台使用帮助”。点击打开原生 dialog；标题“怎么使用”，右上角关闭按钮。弹窗宽度最多 640px，高度最多约 80vh，内容内部滚动。支持 Esc、点击遮罩、关闭按钮关闭；Tab 在弹窗内循环，关闭后焦点回到触发按钮。默认关闭，不主动弹出。

弹窗内只保留两个角色选项：

**我是买家：**

1. 复制买家 Skill 地址，发给 Agent。
2. 选择商品、规格、数量，先让 Agent 确认总金额。
3. 打开 Agent 给出的授权地址，在自己的浏览器登录/注册并批准。
4. 打开支付宝完成付款，让 Agent 查询订单，paid 才是成功。

**我是店主：**

1. 将商家 Skill 发给 Agent。
2. 提供商品名称、数值价格、库存、图片、描述及需要的规格。
3. Agent 发起设备码授权，店主打开返回链接，登录、必要时改初始密码，再批准。
4. Agent 保存店铺资料，创建目录/字段、上传图片、保存商品和规格、上架。
5. 打开公开商品链接检查；后续改价、库存、下架和订单查询继续交给 Agent。

商家页签提供可复制资料模板和一句说明：当前一套部署只有一家店，没有同平台多商家注册入口。不要把不同目录当成不同店铺，也不要引导其他商家使用现有店主账号。

所有指南都是公开说明，不读取私有商品、订单或令牌，也不在帮助弹窗输入密码/验证码。用户实际授权继续使用现有授权页。剪贴板不可用时展示可选文本；无脚本时商品浏览链路正常，页脚仍提供两份 Skill 文档链接。

### 7. 授权与密码页：清晰区分登录和批准

| 页面                  | 可见内容                                            | 主操作与状态                                              |
| --------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| `/authorize/device`   | 设备短码、使用目的、回到 Agent 的说明               | 提交真实 user_code 到既有 `/oauth/device`                 |
| `/authorize/buyer`    | 当前服务端选定步骤、对应手机号/验证码/密码字段      | 人机验证 → 短信 → 设置密码或登录 → 批准；沿用服务端阶段   |
| `/authorize/merchant` | 店主登录；必要时突出初始密码修改                    | 登录后仍显示“还需批准”；没有商家注册                      |
| 批准结果              | 服务端确认为成功后提示“授权已批准，回到 Agent 继续” | 不能按钮点击即成功；没有待批准请求则给重新发起说明        |
| `/admin`              | 登录或密码维护                                      | 无商品、订单、经营指标                                    |
| `/authorize/account`  | 脚本 Key 前缀及撤销状态、一次性 secret              | 与 Agent 授权分开；Cookie Path 问题先修复再扩展浏览器操作 |

客户端不发明 Agent 名称、申请权限、短码或成功状态；只有模型确实提供时才显示对应元数据。授权等待、过期或错误给明确下一步，不要求用户把密码发给 Agent。

### 8. 页面与接口映射、状态统一

| 页面           | 数据能力                              | 用户操作                           | 权限                      |
| -------------- | ------------------------------------- | ---------------------------------- | ------------------------- |
| 首页           | store、products                       | 商品横幅进入详情；查看全部商品进入列表 | 匿名                      |
| 商品列表       | products，已知目录时 schema           | 搜索/筛选、下一页、进入详情        | 匿名                      |
| 商品详情       | products/{id}、schema、media          | 选规格/数量，复制购买请求          | 匿名，不下单              |
| 问号弹窗       | 既有买家/商家说明与 Skill 地址        | 打开、切换角色、复制指南、关闭     | 公开说明，不读取私有数据  |
| 买家/商家授权  | 已有身份服务与 OAuth 交互             | 表单、改密、批准                   | Cookie 与服务端交互       |
| 商品与订单写入 | 商家 CRUD、买家 orders、manage/orders | 由相应 Agent 调用                  | 对应 OAuth Bearer + scope |

| 场景                  | 页面表现                             |
| --------------------- | ------------------------------------ |
| 店铺资料未发布        | 不显示假的介绍，商品仍正常展示       |
| 商品为零 / 筛选无结果 | 明确空状态；筛选时可清除条件         |
| 读取接口失败          | 显示错误与重试，不冒充零商品         |
| 下架或删除            | 不可收录 404，可回列表               |
| 缺图或 Schema 失败    | 主信息仍可读，图片占位/字段标签回退  |
| 部分规格售罄          | 保留售罄信息，仅可用规格支持购买协助 |
| 复制失败              | 可手动选中复制                       |
| 帮助默认状态          | 关闭；正文不出现使用步骤或角色选项   |
| 帮助关闭              | Esc/遮罩/关闭按钮均可，焦点恢复      |
| 登录完成              | 仍需批准，不能当成 Agent 已获权限    |

手机首页为介绍、商品数量与列表入口、封面与商品摘要；详情为标题、图片、价格/规格/数量、正文。问号始终有文字无障碍名称，不依赖颜色表达状态，不增加固定购买浮层。

### 9. 后续扩展的页面长什么样，先补什么

下面是可评估的后续界面，不是本提案的实施任务。后端接口能力和完整人工网页产品是两回事。

| 后续页面     | 建议布局                                                                     | 已有能力                                 | 必要前置                                                    |

### 10. 不同商家如何使用：当前能力与多商家方向

**当前是单店部署。** PRD 第 1、3、4、8.1 节以及 shouldCreateStoreMerchant / ensureStoreMerchant 都约束启动时只有一个店主。授权页仅让已有店主登录和批准，未提供商家自助注册、平台管理员新增商家或切换店铺的生产接口。

使用现有项目给不同商家服务的可行方式，是每位商家一套独立部署，配置其店主账号、公开地址、支付与基础设施参数。每套仍为一个应用进程；店主在自己的部署授权 Agent，再由 Agent 配置店铺资料、目录、商品、规格和库存。不是给其他商家现有店主密码，也不是在同一部署增加商品目录冒充开店。

若希望所有商家进入同一平台，建议的完整流程是：平台管理员开通商家 → 商家登录并修改初始密码 → 保存自己的店铺资料 → 通过 Agent 管理商品 → 获得独立店铺链接 → 买家访问对应店铺。可先做管理员开通，不自动假设自助注册。

这需要另立多商家产品提案，覆盖账号开通与停用、店铺身份和公开路由、店铺与商品/图片/订单的隔离、各店支付配置，以及浏览器身份/Agent 授权边界。现有数据表中存在 merchant_id 和目录归属，不代表完整开店闭环已上线。本轮仅解释，未修改后端或开启多商家。

## Risks / Trade-offs

- [PRD 不允许人工商品后台] → 当前方案使用店主指南和 Agent 流程，人工页面仅作为后续布局建议，另立范围。
- [主首页规格与前一实施增量未同步] → 实施前先处理 `frontend-experience-design` 的规格状态，本方案不自动归档或覆盖。
- [跨目录 q 搜索 PRD 与规格/代码不同] → 不修改查询含义、不宣称仅搜索标题；先统一源文档。
- [公开目录列表缺失] → 不显示伪分类；仅在已知 catalog_id 上下文提供目录筛选。
- [共享 seam 缺字段筛选参数] → 在原查询应用层接入，保持一份验证和一份商品读取，不在组件模拟过滤。
- [价格单位、图库、时间是自定义文本] → 按实际目录映射展示，不生成系统未支持的预约或小费功能。
- [API Key Cookie 与 OAuth Origin 问题] → 本方案继续使用现有 Agent 流程；浏览器新账号功能单独解决，不以测试令牌补缺口。
- [旅游商品英文长文/长标题] → 原图比例、自然换行、窄阅读列、折叠技术信息，手机先放购买协助操作。

## Migration Plan

本轮只提交方案和独立预览附件，不改变运行中的页面、数据库或商品。后续实施分三步：

1. 整理已有首页增量与搜索事实差异，确认本方案生效规格；按用户最新要求收紧首页三块主体，使用说明迁入问号弹窗。
2. 接入列表查询参数、Schema 标签与字段展示、规格/数量购买协助、问号帮助弹窗；沿用已有应用层和表单。
3. 检查桌面/手机/键盘/禁用脚本/缺图/缺字段/无库存/授权失败。先跑受影响检查，再运行仓库门禁；无需创建真实订单或发送真实短信做展示验证。

不需要数据迁移。回退使用之前的页面实现；商品记录、授权协议和支付行为保持现有事实。后续人工后台或直接网页购买使用独立提案，不附带实施。
