# 基于现有接口的前端页面方案

日期：2026-10-09。状态：方案已完成，尚未实施应用任务。

先看 [页面设计方案](./design.md)，它包含首页、列表、详情、问号帮助弹窗、授权与密码页的展示规则、线框、接口对应、错误状态与手机布局。第 10 节说明现有单店模式的商家使用流程，以及未来多商家平台需要补齐的能力。

- [提案](./proposal.md)：问题、范围与能力。
- [页面行为规格](./specs/frontend-page-journeys/spec.md)、[首页规格增量](./specs/public-pages/spec.md)：可验收的 Requirement 与 Scenario。
- [实施任务](./tasks.md)：17 项后续任务，保持未勾选。
- [HTML 预览](./preview/index.html)：只保留店铺首页、商品列表、商品详情三个页面，使用 6 件已上架商品的公开内容快照：原始成都夜游，以及 5 款展示样品。店铺名称与介绍是明确标注的排版示例；预览本身不连接业务接口。

列表只渲染一张封面，使用 4:3 比例覆盖原图高度；卡片等宽等高，标题固定预留两行，超出省略，价格行对齐，完整名称可在悬停提示和详情页阅读。详情附图默认收起，展开高度为 140–220px，重新进入详情恢复收起。截图与逐项验证 JSON 是本机生成附件，保存在 Git 忽略的 `tmp/`，不随源码提交；重新生成的同类文件由 `.gitignore` 排除。

本地预览运行于 `http://127.0.0.1:8881/`。也可直接打开 HTML，照片及样品插画封面随附件保存在 `preview/assets/`。首页顺序为“店铺介绍 → 商品数量与列表入口 → 商品横幅”；横幅上方直接显示“共 6 件商品”和“查看全部商品”，进入列表无需滚过横幅。6 个横幅支持横向滚动、左右按钮和键盘方向键，商品横幅和列表卡片进入各自的详情。列表默认显示总数，搜索同时显示匹配数量与店内总数；详情显示对应的图片、价格、库存和介绍。右上角问号打开买家/店主帮助弹窗，默认关闭。

“查看全部商品”使用品牌绿色底、白色文字与小箭头，位于商品数量右侧，首屏可见；帮助入口保留透明底绿色 SVG 问号，两处图标统一为 1.75px 线宽并保留至少 44px 点击高度。总数来自已确认完整的公开商品快照，不能将未完成分页的条目数量显示为全店总数。

预览图片安全边界：JSON 快照中的图片引用只能选择固定白名单中的 8 个本地资产，实际 `src` 使用白名单返回的常量路径。未知路径、外部地址、`javascript:` 和 `data:` 地址均不显示；商品文字仍可阅读。修复了两处原先将 DOM 快照文本直接赋给图片 `src` 的 CodeQL 告警来源，未关闭或抑制扫描。GitHub 的最终扫描结果需在修复提交推送后确认。

现有产品继续通过 Agent 管理与购买。当前一套部署只有一家店，没有其他商家注册开店入口。人工商品后台、网页收银台、订单中心的布局建议单列在设计第 9 节，多商家接入列在第 10 节，均未包含在本变更实施任务中。

本次按用户要求，通过既有商家图片上传、商品创建及上架接口新增 5 款展示样品：人民公园盖碗茶体验（￥88/person）、熊猫基地半日游（￥168/person）、老城街巷美食漫步（￥128/person）、川菜厨房体验课（￥228/person）、锦江日落摄影漫步（￥198/person）。名称与须知均标明展示用途，价格、库存和时间为示例。封面插画经图片接口上传，真实应用 `http://127.0.0.1:3000/products` 可以查询这 5 件商品。原始夜游商品保留；应用的前后端源码没有在本次修改。HTML 仅同步本次公开数据快照，后续后台数据变化需再次更新快照。

验证：OpenSpec 严格校验通过；三页在 1440px / 390px 下均无横向溢出；搜索、数量、图片、浏览链路及弹窗角色切换、键盘焦点循环/恢复、Esc、遮罩和关闭按钮检查通过，手机弹窗内部可滚动，浏览器无错误日志。应用仓库门禁结果另见本轮执行记录。
