# Proposal

## Why

很多部署只需要商品被搜索引擎和 Agent 发现，不需要买家下单。现在进程把图形验证、短信和支付商户密钥当成始终必填，公开文档也把买入写成主路径，只做 SEO/GEO 的店无法少配这些厂商账号。

## What Changes

- 新增启动开关 `MERCLINK_PURCHASE`。只有精确值 `1` 开启买入。未设置、空字符串和 `0` 都是关闭。其他值拒绝启动。关闭是默认，也是升级后的行为。
- **BREAKING**：已有部署若不把该变量设为 `1`，升级后不能下单，买家授权、图形验证、短信和支付商户密钥不再是启动必填。开关只在进程启动时读取，运行中不热切换。
- 关闭时不展示、也不要求配置买家登录、图形验证、短信和支付商户。商家设备码、店主密码、目录商品、图片、店铺资料、店面、Redis 和对象存储保持不变。
- 公开文档 `/skill.md` 一律改称用户 Skill，路径不变。关闭时正文只教公开查询。开启时同一份文档仍称用户 Skill，并继续教下单和支付。内部买家账号、买家令牌和 `order:*` scope 不改名。
- 新增错误码 `purchase_disabled`，业务码 `40302`，HTTP 403。关闭时买家下单和买家订单查询在事务前返回它，不扣库存，不调用支付。
- 关闭时只含订单 scope 的设备码授权被拒绝，不打开注册页，不发短信，不加载图形验证码。商家授权页保持只有登录和批准。

## Capabilities

### New Capabilities

- `purchase-mode`: 启动时决定这一家店是否接受买入，以及关闭时哪些配置、页面和调用必须缺席。

### Modified Capabilities

- `app-runtime`: 图形验证、短信和支付商户密钥只在买入开启时必填。数据库、店主、授权签名和公开地址始终必填。
- `shared-api-contract`: 增加 `purchase_disabled` / `40302`，并规定它不是可重试的依赖失败。
- `order-placement`: 买入关闭时，买家也不能创建订单或读取自己的订单；商家读取历史订单仍可用。
- `agent-authorization`: 买入关闭时，订单 scope 不得进入买家注册或登录。商家 scope 行为不变。
- `buyer-registration`: 买入关闭时不得创建注册挑战、不得调用验证码或短信。开启时现有顺序不变。
- `alipay-payment`: 买入关闭时不创建支付，不因超时任务调用支付端口或改旧单状态。通知验签失败仍不改状态。
- `agent-skills`: `/skill.md` 改称用户 Skill；关闭时不得教下单，开启时必须教下单。
- `public-pages`: 关闭时落地页、商品页和 `/llms.txt` 不得引导购买；开启时购买引导指向用户 Skill。
- `cross-slice-acceptance`: 默认关闭时商家仍能上架并被公开发现；买家付费闭环只在 `MERCLINK_PURCHASE=1` 时验收。

## Impact

- 环境样例、README 和 `compose.yaml` 要标明买入默认关闭，以及开启后才需要的厂商变量。`MERCLINK_DEV_STUBS` 仍只在 development 生效，不能代替这个开关。
- 公开 Skill、`/llms.txt`、落地页和商品页购买引导随启动值变化。`/skill.md` 路径、商家 Skill 和店面 Skill 路径不变。
- 下单、买家订单查询、买家授权和短信发送在关闭时失败关闭。支付通知路由仍挂载，但没有商户密钥时不能把订单改成 `paid`。
- 不新增依赖，不新增路由表，不把开关存进数据库，不做 GEO 监测。
- 未归档的 `2026-10-08-api-envelope-and-smoke` 禁止新增错误种类。本变更明确只增加 `purchase_disabled`。归档时不要把那条禁令合并回来。
- 未归档变更已经改过 `/llms.txt`、Skill 和落地页文案。实现时在当前已落地文案上改，不要退回主规格里的短文案。归档冲突以本变更为准：默认不买入，文档称用户 Skill。
