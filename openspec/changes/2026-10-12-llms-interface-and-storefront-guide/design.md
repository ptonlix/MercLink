# Design

## 决定

`/llms.txt` 继续只有 `先读`、`页面`、`接口` 三个 H2。接口文档是路径索引，放进「接口」，不新开一节，也不把每条已登记路径抄进目录。链接文案写明它给人看，调用仍以 Skill 为准。这样目录能指路，又不会变成第二份协议。

`/api/v1` 保留。它仍是机器前缀和 OAuth 资源标识。目录必须同时说它不是文档，避免再把 404 前缀当成入口。

首页使用介绍沿用现有无脚本 radio 切换，但身份只留两档：用户，和「我是店主，想配置」。店主面板里再用两个小节区分「上架商品」和「修改店面」，不再把它们做成并列身份。改店面四步只复述店面 Skill 已有边界：把 Skill 交给 Agent、店主在浏览器批准、说明外观且事实用槽位、预览后确认激活。不在页面上写发布接口、scope 字符串或验收命令。那些仍只在 `/storefront/skill.md`。

上架小节不放「查看店面 Skill」，避免两条工作流抢同一个入口。买入关闭时，改店面文案说查找商品走用户 Skill，不写购买、下单或付款。

## 不做

- 不改三份 Skill 正文，不新增 Skill 路径。
- 不把 `/interfaces` 的字段页嵌进 `/llms.txt`。
- 不把改店面步骤放进商家 Skill。
- 不改店面激活后的保留路径。激活中的店面仍不能替换 `/interfaces` 或 `/llms.txt`。

## 失败时

目录生成失败沿用现有公开页错误，不回退到一份不含接口文档链接的静态文件。使用介绍把上架和改店面拆回并列身份，或改店面小节缺店面 Skill 时，落地页测试失败，不在页脚用一个孤立链接代替。
