# Proposal

## Why

这一套部署只有一家店，但公开页、注册页和支付前页面都焊在支付进程里。商家不能用自己的 Agent 改店面，也就不能按自家行业重做页面。需要一条只替换这一家店店面、且不让上传代码在服务端执行的路径。

## What Changes

- 抽出这一家店当前的店面源码，供商家 Agent 下载、自由改写、本地预览和打包。没有模板库，也不做多店或多套主题。
- 商家推送源码归档和静态构建结果。服务端只存档和按字节托管，不安装依赖，不编译，不执行上传代码。
- 激活切换当前发布指针，不重启进程。回滚指回上一份发布；没有定制发布时继续用内置页面。
- 注册、登录、批准和下单确认的外观可以放进店面，以便统一风格。人机验证、短信、会话、OAuth、支付通知、管理页改密和支付宝收银台仍由现有进程处理。
- 新增一份公开店面 Skill，写明能改什么、不能动什么、修改规范和验收。买家 Skill 与商家 Skill 的购买和管理合同保持不变。
- 凡是会随后端变化的事实都用槽位，不只价格。店铺介绍、商品列表、商品名称、封面、公开字段、规格、库存和订单状态都由服务端按当前接口现渲染。商家改版式，不把这些事实烤进 HTML。没有这类事实的营销页仍按静态字节分发。
- sitemap 不得把未知地址回退成首页。下架、已删除或非公开商品地址仍不可收录。这两条由服务端执行，不只写在 Skill 里。
- **BREAKING**：定制发布激活后，不含事实槽位的页面改由该发布响应，不再套用内置落地页的文案、页脚和 JSON-LD 规则。含店铺、商品或订单事实的页面仍由服务端按当前接口渲染。发现文件、Skill、API 和授权协议地址仍由服务端提供。

## Capabilities

### New Capabilities

- `storefront-release`：下载当前店面源码，接收静态发布，激活和回滚，且保留路径不能被覆盖。
- `storefront-skill`：公开店面 Skill 指导商家 Agent 改页面，并规定不能动的协议和验收。

### Modified Capabilities

- `public-pages`：无激活发布时内置页规则不变；有激活发布时，文案和 JSON-LD 不再约束商家 HTML，但商品规范地址、sitemap 和下架地址仍由服务端保证可发现。
- `agent-skills`：增加第三份公开 Skill 的入口，且不改变买家与商家 Skill 已有的路径合同。
- `agent-authorization`：替换线上店面使用独立权限，已有商品写权限不能自动换页。

## Impact

- 新增店面源码、发布存档、激活指针和保留路径优先的静态分发。对象存储继续只用已配置的 S3 或 MinIO。
- 新增店面下载、发布和激活路由，登记到 `src/shared/api-routes.ts`。不新增支付回跳即成功的接口。
- 新增 `/storefront/skill.md` 和对应测试。买家 Skill、商家 Skill 的现有教法不改。
- PRD「不做独立站装修、主题」需改为：允许这一家店的 Agent 替换公开店面，仍不做多店、主题市场和购物车。
- 不拆微服务，不新增依赖，不在应用容器内构建商家源码。
