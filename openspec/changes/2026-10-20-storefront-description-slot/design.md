# Design

## 背景

`product.description` 已在店面槽位允许名单里。内置商品页和起始模板会声明它。`inspectDocument` 不要求商品页声明它，未声明的已发布模板也不会被改写。`/storefront/skill.md` 的事实槽位清单停在名称、封面、字段、规格、库存、可售状态和价格，所以 Skill 和运行时不一致。

## 目标

让店面 Skill 说出这个可选槽位的名字、填入规则，以及不声明时的结果。

## 非目标

- 不把 `product.description` 变成商品页必填槽。
- 不改写已激活的自定义店面，也不在服务端为缺少该槽的模板自动插入描述。
- 不改描述的存储、搜索、Markdown 或 JSON-LD。

## 决定

1. 在事实槽位清单中给出空元素 `<merclink-slot name="product.description"></merclink-slot>`。
2. 写明它可以不声明。没有该槽位的发布仍可激活，服务端不改写旧模板，页面也不自动补描述。
3. 写明声明后填入当前商品自己的描述，保留换行，空描述时槽位为空。禁止把某一件商品的描述写进 HTML，也禁止另起槽位名。
4. 首页和商品列表不必声明它。必填商品槽仍是名称、封面、价格和可售状态，外加列表的 `products.next`、商品页的字段和规格。

## 失败时

Skill 漏写该槽位时，测试失败。发布校验仍不因为缺少 `product.description` 而拒绝模板。
