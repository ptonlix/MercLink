# 界面设计与验收规范

本规范服务于 PRD 的单店、Agent 购买与授权流程。实现变更见 `openspec/changes/2026-10-12-cohesive-ui/`。设计方法参考 finesse-ui 的 audit、redesign 和 commerce 指南，产品范围以 PRD 为准。

## 视觉方向

真实商品照片承担店面的表现力。公开店面使用冷石墨、冰白和冰青色、无衬线标题；授权与文档保留深暖墨、象牙与黄铜基础主题。下表是基础令牌，店面覆盖值见首页章节。中文不使用过紧行高。不下载字体，不引入动画或组件库。

| 角色 | 基础值 | 用途 |
| --- | --- | --- |
| 背景 | `#161311` | 全站画布 |
| 表面 | `#211d19` | 表单和信息区域 |
| 高层表面 | `#2b251f` | 悬停和选中区域 |
| 主文字 | `#f3ece2` | 标题、正文、主按钮 |
| 次文字 | `#b7aa9a` | 说明、辅助字段 |
| 强调 | `#d7b07a` | 价格、选中、链接 |
| 错误 | `#e7a398` | 带文字解释的错误 |

使用现有 `--ml-*` CSS 变量，补充表面、边框、圆角和间距语义。正文 16px 起，长正文行高约 1.8；桌面主标题 40–56px，手机 28–34px，允许长标题换行。控件至少 44px 高，焦点可见，状态不只靠颜色表达。

## 页面结构

### 店铺首页

最新变更见 `openspec/changes/2026-10-12-orbit-storefront/`。首页、商品列表、详情统一冷石墨 `#0c1218`、冰白 `#edf4f7`、冰青 `#9ee8e0` 和无衬线标题。

标题前显示与浏览器图标一致的成都大熊猫头像，装饰熊猫沿真实字母位置爬行；完整真实简介位于标题下方并一次性打字展示。可暂停动画，减少动态效果时直接显示全文与静态熊猫。

商品采用悬浮椭圆轨道轮转：卡片沿弧线改变水平、高度与深度位置，前景放大、侧后方缩小并倾斜，阴影提供悬浮感。每个商品仅一个链接，不复制、不平移整条带。悬停暂停并抬起，键盘聚焦将商品转到前方；左右图标可逐项浏览，点击直接进入详情。减少动态效果或无脚本呈现完整静态卡片。

浏览路径只有首页 → 商品详情 → 返回首页，详情移除重复导航与返回列表入口。首页移除常驻查看更多，商品多时在首页翻页；原有列表地址只保留兼容用途。静态源码包仍遵循现有槽位与分页协议。

页脚只保留简洁平台署名及“如何使用”功能入口，展开原有买家/店主步骤及发现链接。

### 商品列表与详情

列表沿用统一冷色令牌和摄影卡片，宽屏三列、中屏两列、手机一列，保留分页。
详情展示一张大图，下方为按 URL 去重的其他图片缩略图（已有商品中另存为不同 URL 的重复封面引用也已清理），隐藏当前大图对应的小图；缩略图、左右图标和键盘同步切换。默认英文介绍，通过选项卡切换中文，无对应语言不虚构翻译。未知字段继续显示。
购买需求按钮缩窄，与右侧买家 Skill 图标链接同排。复制成功、失败手动复制反馈继续保留。不改变 Agent 确认商品、规格、数量和价格的流程。

### 授权与账户

使用紧凑、安静的单列操作区。步骤明确当前项，输入、帮助、错误、主次操作有稳定间距。表单字段、提交地址、验证码与批准顺序不改变。不新增店主管理后台或第三方登录。

### 接口文档与异常状态

文档沿用品牌色但不叠加颗粒或持续动效。桌面分组目录与正文并列；手机目录可折叠，正文优先。路径和字段用等宽字，描述用正文体，当前页面有明确选中状态。

空商品、图片失败、不可公开商品、请求失败均说明状态和下一步；不把读取失败说成没有商品。支付结果只反映服务器状态。

## 实现边界

- 公开事实继续来自现有 public seam。SSR、Markdown、JSON-LD 与可见内容一致。
- 字符只做一次正确的 HTML 转义，不通过插入未处理的原始 HTML 修复标题。
- `views.tsx` 同时服务内置页面与默认源码包；样式在 `.page` / `.ml-auth` 内约束，所有默认文档具备 viewport。
- 内置图集可读取已有字段；静态模板保留 cover、field、variant 槽位与全部公开事实，不假装具备未打包的 React 交互。
- 不新增依赖、路由、数据表、筛选排序、购物车、推荐或直接结账。

## 验收

1. 检查 320、390、768 和桌面宽度；页面不横向溢出，长标题和按钮不遮挡，首图与操作易发现。
2. 图集、首页页卡、身份选择、复制及文档目录可键盘操作。手机页卡直接点击；减少动态效果时无自动运动或指针景深。
3. 检查无图、空商品、长正文、符号标题、缺货和查询失败。公开事实无脚本可读。
4. 验证默认模板填充后的封面、名称、价格、字段、规格与授权表单。
5. 跑受影响的 Vitest、typecheck、boundaries、`pnpm run check`；改公开页/授权/店面还需完整冒烟。环境缺失时明确记录，仅覆盖检查通过不等于完整冒烟通过。

## 行程商品详情

集合地址 `meeting_point`、时间 `tour_time` 与预约链接 `other_payment` 来自现有商品字段，展示在图片旁边，不在下方事实表重复。未提供地址不生成地址。行程人数默认 1，可加减；下限 1，有限库存时不超过所选规格库存。复制购买需求带人数，外部预约链接只打开对应页面。无脚本显示默认人数与交给 Agent 的说明。

## 浏览器图标

根布局使用静态 `src/app/icon.svg` 与 `src/app/favicon.ico`：冰青底、冰白脸部和石墨五官的大熊猫头像，与标题前 Logo 使用相同图形，ICO 包含 16/32/48px。Next.js 自动声明图标，首页与商品详情保持一致，不依赖客户端脚本。

## 远端购买模式兼容

`MERCLINK_PURCHASE` 遵循启动时开关，默认关闭。关闭时保留行程事实、人数、外部预约链接和用户 Skill 图标，隐藏站内购买需求复制及购买引导。开启时复制按钮与 Skill 图标同排，复制需求包含人数。页脚“如何使用”根据开关展示查找或购买步骤，保留店主上架与店面配置两个分支，并传入真实店铺联系方式。接口文档保留远端新增的请求/响应示例和本地新版样式。
